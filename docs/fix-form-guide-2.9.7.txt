FIX form
--------
Starting DR and its source are visible above Calculate. Choose a saved sight,
manual coordinates, or explicitly choose current boat position. The latest
included eligible sight with a valid saved DR supplies the default; no usable
saved DR leaves blank entries and blocks calculation/chart navigation. Old XML
without DR attributes also leaves DR unavailable. Manual and explicit choices
survive ordinary recalculation. Inputs accept the existing OpenCPN angle formats
and readouts follow its preferred coordinate format.

FIX latitude, longitude and angular RMS sit above the algorithm selector and
Show fix on chart. Vessel motion offers Stationary, One COG and SOG, and Each
sight's DR Shift. Included shifted sights select the last option by default;
otherwise Stationary is the default. The stationary algorithm is disabled for
running fixes, which use the existing running-fix solver. Running fixes show
UTC reference time, initially the latest included sight. More options retains
UTC/local epoch override, Latest sight, clock-correction selection and solver
diagnostics. The stationary and running solvers are unchanged. Stationary Hc
and Ho-Hc/RMS are additional display diagnostics.

Desktop keeps a compact horizontal layout; Android uses full-width touch
controls, scrolling and vertical sight details. The form ignores old oversized
desktop geometry by saving a separate Fix297 setting. Invalid inputs clear old
results and chart navigation instead of allowing a stale result to be plotted.

Lunar accuracy (#341)
--------------------
Choose Check at entered UTC in Lunar Results. Enter an independently known
position at the distance-reading epoch and use reliable entered UTC (including
the existing manual clock correction). Saved DR pre-fills the fields but must
be confirmed; no boat position or fitted lunar position/time is substituted.
Changing these check-only fields does not edit the saved sight or apply a lunar
clock correction. Invalid position leaves True LD visible when available and
reports cleared distance/error unavailable.

The existing WGS84 forward model predicts the raw sextant distance, including
index error, limb contact, refraction/disc flattening and parallax. Its net
correction at the independently supplied geometry is subtracted from the
measured distance:
  Cleared LD (model corrected) = observed LD + True LD - predicted raw LD
  Lunar error (arcmin) = 60 * (Cleared LD - True LD)
Positive error means the observed distance is too large. This is explicitly
labelled model-based clearing, not Direct Triangle clearing from measured
altitudes. It works at the distance epoch for simultaneous and sequential
observations, without fitting away the distance error using their altitudes.
Known-position, UTC, atmosphere and instrument errors also affect this check;
it is not solely an estimate of sight-taking skill. The existing joint
UTC/position solution, branch residuals and uncertainties remain separate.

HTML presentation correction (same 2.9.7 development PR)
------------------------------------------------------
The initial 2.9.7 HTML used page images followed by line-by-line extracted text
labelled "Selectable transcription". That label was an authoring choice, not
missing content, but the approach omitted the reader improvements already
recorded in production docs/practical-guide.md for 2.8.15/2.8.16.

tools/build_practical_html.py now adopts that established conversion, adapting
it to Bob's 70 development pages and the seven-page definitions appendix.
Content and source-page order follow the bundled PDF; the PDF itself is
unchanged. Grouped contents, descriptive page headings, joined paragraphs,
actual bullet lists, compact source captions and consistent Previous/Contents/
Next navigation replace the scan-and-transcription presentation. The 57
complete illustrated compositions retain screenshots, arrows and annotations
together. Reading-size previews fit the native reader; full-size lossless
views retain small labels and selectable illustration text.

The complete definitions source is reflowed into definitions.html with section
anchors, original credits/revision and reference link, matching later 2.8.x.
The first-page definitions, lunar and historical accuracy references work.
Windows-compatible UTF-8 metadata/numeric entities and the established native
12-point reader font are retained. No script, remote image/font or desktop
guide asset is introduced into Android.

Rebuild only HTML without re-exporting the PDF:
  python tools/build_practical_html.py
The full PDF merge builder delegates its HTML conversion to the same tool,
so regeneration retains this presentation. html-conversion.json records all
70 page titles, source prose and figure bounds plus all 107 definitions blocks.
Validation compares those blocks with the generated HTML, checks links and
packaged assets, and renders all 77 pages in the native wx reader without
horizontal overflow.
